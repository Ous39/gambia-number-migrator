# Project Audit — 10 July 2026

## Outcome

The recovered application source was audited across the Expo mobile app, Express API, React admin portal, shared migration engine, PostgreSQL migrations, Docker configuration, and Windows launch scripts. The original upload was truncated during `docs/design/dashboard-reference.png`; all application source files preceding that optional design asset were recovered.

## Critical fixes completed

- Removed the unconditional `LOCAL-UI-TEST` premium unlock from the migration preview. Contact changes now require a confirmed unlock.
- Removed client-generated OTP trust and offline payment success. Payment intent creation and OTP verification now happen through the API.
- Added five-minute OTP expiry, hashed OTP storage, and a five-attempt limit.
- Added `003_secure_payments.sql` for OTP, payment timestamp, and lookup fields.
- Protected Wave and APS webhook routes with provider-specific secrets and rejected unknown payment statuses.
- Prevented payment APIs from returning database rows containing OTP hashes and internal metadata.
- Added a production startup guard for the default JWT secret.
- Removed the pre-filled admin password from the login form.
- Made the production seed password depend on `ADMIN_INITIAL_PASSWORD`.
- Fixed missing-payment handling for manual admin confirmation.

## Payment UI improvements

- Updated the journey to match the supplied reference: **Method → Details → Verify → Success**.
- Kept Wave and APS selection, a clear D100 amount, phone entry, OTP verification, success receipt, and back navigation.
- Updated copy so the interface no longer claims that offline UI actions are successful payments.
- Kept theme-aware cards, controls, validation states, and responsive mobile sizing.

## Validation

- Static inspection completed for source paths, routes, schemas, migrations, configuration, payment state transitions, migration gating, and credential defaults.
- Package installation was attempted twice. The npm registry repeatedly returned HTTP 502 for React Native/Metro packages, so full TypeScript, test, Expo export, and admin build execution could not be completed in this environment.
- Before running locally, install dependencies, apply all migrations (including `003_secure_payments.sql`), then run `pnpm typecheck`, `pnpm test`, and `pnpm build`.

## Production integration required

This build provides a safe development OTP flow when `PAYMENT_TEST_MODE=true`; it is not a live Wave or APS integration. Before launch:

1. Set `PAYMENT_TEST_MODE=false`.
2. Integrate the official provider checkout/OTP APIs.
3. Validate callbacks using each provider's official signature scheme, replacing the temporary shared-secret header adapter if required by their specifications.
4. Configure strong `JWT_SECRET`, `ADMIN_INITIAL_PASSWORD`, `WAVE_WEBHOOK_SECRET`, and `APS_WEBHOOK_SECRET` values outside source control.
5. Perform provider sandbox, replay, duplicate-callback, timeout, cancellation, and settlement tests.
