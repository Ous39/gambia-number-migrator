# Full Fix Report — Backup and Notifications

## Backup defects fixed

- Replaced the unsafe single-value full backup with chunked local storage.
- Added complete write verification before any migration/cleanup continues.
- Added full chunk-count validation before restore changes contacts.
- Preserved compatibility and automatic conversion for old backups.
- Added unique backup IDs, a 30-backup retention policy, orphan-chunk cleanup, clear-data cleanup, and functional delete controls.
- Empty contact books no longer produce misleading successful backups.
- Backup and restore history continue to record totals, skips, failures, and backup IDs.

## Notification system added

- Device push-token registration for Android and iOS.
- Admin composer with title, message, and audience selection.
- Persistent notification history and admin audit logs.
- Expo push batching (100 tokens per request) with sent/failed ticket totals.
- Mobile notification permission request, Android channel, foreground display, tap-to-inbox navigation, inbox refresh, and offline cache.
- Blocked devices cannot register tokens or read notifications.

## Required setup

- Apply migrations `001` through `009`. Migration `009` adds migration-prefix integrity constraints; the migration runner now tracks each file transactionally.
- Run `pnpm install` so `expo-notifications` is installed.
- Set `EXPO_PUBLIC_EAS_PROJECT_ID` and configure Android FCM/iOS APNs credentials in EAS.
- Use a development/release build for Android remote push testing; Expo Go does not provide remote push on Android for this SDK.
